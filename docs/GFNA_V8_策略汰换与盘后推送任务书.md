### 7.2 数据实现方案（推荐 B）

- **方案 B（推荐）**：在 `build_candidates` 中增加 `_enrich_history(frame, trade_date, db, lookback)`：
  - 一条 SQL 读取“当日合格股票池 + 最近 N 个交易日”的 `code/trade_date/open/high/low/close/volume/amount/adj_factor/is_limit_up`；
  - 在 pandas 中按 code 计算衍生列，join 回当日横截面；
  - 只对 c1–c4 调用，N 按策略需要（c1 21、c2 40、c3 121、c4 2）。
  - 实盘每日 1 次查询；2 年回测约 25 个调仓日 × 4 策略 = 100 次窗口查询，预算单策略 2 年回测 < 5 分钟。
- **方案 A（备选）**：把 `high20_prev / high40 / low40 / high10 / low10 / vol_ma20_prev / roc120 / prev_is_limit_up` 落成 `fact_feature_daily` 新列，需要 Alembic 迁移 + 全量特征回填 + 断点校验。只有当方案 B 性能不达标或后续策略大量复用窗口指标时才升级到方案 A。
- 衍生列定义：

| 列 | 定义 |
|---|---|
| `adj_open/high/low/close` | `* adj_factor`；`adj_factor` 为空时用原始价并记录数据质量告警，不补 0 |
| `high20_prev` | `max(adj_high[t-20..t-1])` |
| `high40/low40` | `max/min(adj_high/low[t-39..t])` |
| `high10/low10` | `max/min(adj_high/low[t-9..t])` |
| `vol_ma20_prev` | `mean(volume[t-20..t-1])` |
| `roc120` | `adj_close[t] / adj_close[t-120] - 1` |
| `high120` | `max(adj_high[t-119..t])` |
| `prev_is_limit_up` / `prev_volume` / `prev_close` | `t-1` 日对应字段 |

### 7.3 策略规格（初始默认值来自 Sequoia 原值，已确认；未做参数寻优）

#### c1 海龟突破（turtle_breakout）

- 最少 K 线：21。
- 条件：
  1. `adj_close[t] > high20_prev`（突破前 20 日最高价）
  2. `amount[t] >= min_amount`（默认 1 亿元）
  3. `adj_close[t] > adj_open[t]`（实体阳线）
  4. `adj_close[t] > adj_close[t-1]`（真涨，防假阳线）
- 排序：`float_cap` 降序（流通市值，对应 Sequoia 口径；字段已在日线横截面中）。
- 参数：`limit=20`、`lookback=20`、`min_amount=1e8`。

#### c2 高窄旗形（high_tight_flag）

- 最少 K 线：40。
- 条件：
  1. `high40 / low40 > mom_min`（默认 1.6，40 日强动量）
  2. `high10 / low10 < tight_max`（默认 1.15，10 日极度收敛）
  3. `low10 >= high_level * high40`（默认 0.8，高位不破）
  4. `volume[t] < shrink_max * vol_ma20_prev`（默认 0.6，缩量）
- 排序：`high40 / low40` 降序（动量最强优先）。
- 参数：`limit=20`、`mom_min=1.6`、`tight_max=1.15`、`high_level=0.8`、`shrink_max=0.6`、`min_amount=5e7`。

#### c3 RPS 突破（rps_breakout）

- 最少 K 线：121。
- 条件：
  1. `roc120` 在**当日合格股票池内**的横截面百分位 ≥ `rps_threshold`（默认 90）
  2. `adj_close[t] >= near_high_ratio * high120`（默认 0.9，接近 120 日新高）
- 排序：RPS 降序。
- 参数：`limit=20`、`lookback=120`、`rps_threshold=90`、`near_high_ratio=0.9`、`min_amount=1e8`。
- 口径差异（有意）：Sequoia 用库内全部代码排名；本系统只在通过前置过滤的合格池内排名，避免 ST/停牌/次新污染分位。

#### c4 涨停洗盘（limit_up_shakeout）

- 最少 K 线：2（t-1、t）。
- 条件：
  1. `prev_is_limit_up == True`（昨日涨停，板块口径：10%/20%/5% 由数据标志决定）
  2. `adj_close[t] < adj_open[t]`（今日收阴）
  3. `volume[t] > vol_mult * prev_volume`（默认 2.0，放量）
  4. `adj_low[t] >= prev_close`（支撑不破）
- 排序：成交额降序。
- 参数：`limit=20`、`vol_mult=2.0`、`min_amount=5e7`。

### 7.4 策略验证与启用门槛

1. **语义测试（测试先行）**：每个策略用合成 OHLCV 构造“必选正样本 + 每个条件各一个反样本”，断言精确代码集合。
2. **无未来函数**：`assert_no_lookahead` 扫描通过；新增 window 计算的索引不得出现 `shift(-`。

5. **参数敏感性**：每个策略关键参数 ±20% 至少 3 组，检查结论方向；不据此选最优参数。

## 14. 任务监控采集降级修复（2026-11-16）

### 14.1 根因

- **个股资金流**：`collect_moneyflow` 只认“当前快照”采集，数据源链不可用时直接抛
  `ProviderError: 所有数据源均不可用`；而 2026-11-13 库内其实已有 5225 行新浪资金流，
  只是质量分母用了全活跃股票池 5562（93.9% < 阈值），既没有“已有数据跳过”，也没有
  缺失代码的新浪补抓，导致同一交易日反复失败。
- **板块成分**：行业板块成分依赖东财，东财 `push2*` 在本网络被重置后，旧逻辑把行业板块
  失败计入全局失败并触发熔断；板块清单偶发取不到时也没有沿用最近交易日清单。结果是
  概念板块明明可以走新浪，整轮任务却被行业源拖成 `failed/quality_failed`，任务监控持续
  显示“数据源均不可用/抓取失败”。

### 14.2 修复

- 资金流：
  - 质量分母改为**当日有行情的股票数**（`fact_stock_daily`），不再用全活跃池；
  - 已有覆盖率达到 `QUALITY_MIN_COVERAGE` 时直接 `skipped/already_collected`，不重复抓取；
  - 数据源链失败时按缺失代码调用新浪 `backfill_moneyflow` 补齐，再按覆盖率判定质量。
- 板块成分：
  - 当日板块清单缺失时沿用最近交易日清单；
  - 概念板块优先，并使用新浪 `Market_Center` 概念成分链，避免东财概念接口拖垮整轮；
  - 行业板块源不可用时只跳过剩余行业板块并保留既有 SCD2 区间，不再把整轮标失败；
  - 新浪“名称未匹配/空成分/冷却期”改为 `skip_reason`，不抛异常、不触发全局熔断；
  - 只有概念板块真实连续失败或预算耗尽时才记 breaker error。
- 任务监控页：`skipped` 的 `already_collected` 等正常原因显示为灰色“已采集，跳过”，
  不再用红色“错误摘要”渲染；补充“部分成功/跳过”筛选。
